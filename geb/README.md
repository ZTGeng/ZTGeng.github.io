# G.E.B. 互动项目

采用 Vite 多页面构建，每章一个独立页面。首页是纯前端 Three.js 互动。一个固定的木雕网格，在两个互相垂直的墙面和地面上，分别投出 G、E、B。拖动只旋转木雕；相机、灯光和接影面始终固定。

## 本地开发

需要 Node.js 20 或更新版本和 npm。本项目的 Vite 独立于主站，命令都在 `geb/` 中执行：

```powershell
cd geb
npm install
npm run dev
```

打开终端显示的地址，默认是 <http://127.0.0.1:5173/geb/>。依赖版本由 `package-lock.json` 锁定，也可用 `npm ci` 安装。当前使用 Three.js 0.186.1 和兼容本地 Node.js 20 的 Vite 6.4.5。

## 构建和静态发布

```powershell
npm test
npm run build
npm run preview
```

生产预览默认是 <http://127.0.0.1:4173/geb/>。

`build` 先重新生成模型，再由 Vite 输出 `dist/`，最后把生成的 `index.html`、`chapters/` 和 `assets/app/` 复制到项目根目录。**请编辑 `src/index.html`，不要手工修改生成的 `geb/index.html`。**

这是为了兼容本仓库现有的 GitHub Pages/Jekyll 部署：将 `geb/index.html`、`geb/chapters/` 和 `geb/assets/app/` 连同源码提交，即可继续由现有站点直接托管，无需线上 Node.js、额外工作流或服务器。构建只复制这些产物，不清空项目目录或未来章节。

也可把 `dist/` 的内容发布到静态站点的 `/geb/` 路径下。资源的 base 固定为 `/geb/`。若部署到其他路径，修改 `vite.config.js` 的 `base` 和章节链接后重新构建。

此前的静态预览服务器 <http://127.0.0.1:8767/geb/> 也能直接预览构建产物；源码修改后的热更新请使用 Vite 开发地址。

## 几何构造

`scripts/volume.js` 自行定义三个粗笔画、带切角的二维字形轮廓，不依赖操作系统字体或书籍插图。以 96³ 体素采样三个正交拉伸体的交集：

```text
M(x,y,z) = G(-z,y) ∧ E(x,y) ∧ B(x,-z)
         = ExtrudeX(G) ∩ ExtrudeZ(E) ∩ ExtrudeY(B)
```

这里沿 Y 投出 B（地面），沿 X 投出 G（左墙），沿 Z 投出 E（右墙）。字形的横向和纵向符号与实际墙面的可读方向一致。

任意三个字形求交并不保证投影完整。本项目使用相容的粗笔画及支撑区域：G/E 的上下笔画、两者的左竖笔画和 B 的竖笔画/横向笔画提供彼此所需的贯通射线。生成器会检查实际投影，而非假设交集自动成立。

随后删除内部面，贪心合并相邻共面的体素表面矩形，得到一个具有外向法线的固定网格。模型尺寸为 2.6，中心位于原点。目前输出：

- 379,776 个实心体素；六邻接检查为 **1 个连通体**，不是靠角点接触的散件。
- **1,696 个三角形**，没有逐体素绘制。
- G/E/B 三个方向在采样分辨率下的轮廓覆盖率均为 **100%**，额外投影像素为零。

```powershell
npm run geometry
```

输出 `assets/model/sculpture.json`、`report.json` 及三个 `projection-*.svg`。SVG 是开发时查看正交投影的诊断文件，**页面不加载它们**。运行时仅加载预计算网格，拖动期间不重新构造几何。

`npm test` 除体素投影外，还会独立光栅化导出的三角形并核对字形，检查网格绕序及有向体积，确保最终绘制的网格与计算结果一致。

## 三路实时阴影

三块接影面位于 `x=-4.4`、`z=-4.4`、`y=-4.4`，法线分别为 +X、+Z、+Y。墙面已从最初的 3.15 外移，避免木雕遮住初始字母；测试会从桌面和窄屏相机向全部字形采样点发射视线，确认没有被木雕阻挡。三盏 `DirectionalLight` 分别位于 `(8,0,0)`、`(0,0,8)`、`(0,8,0)`，指向原点：

| 灯光方向 | 接影面 | 初始投影 | 字形坐标 |
| --- | --- | --- | --- |
| −X | 左墙 | G | 水平 −Z，竖直 +Y |
| −Z | 右墙 | E | 水平 +X，竖直 +Y |
| −Y | 地面 | B | 水平 +X，竖直 −Z |

每块平面只受到对应轴向光的正面漫反射；其他两盏灯与它的法线垂直，不会把正确字母阴影照亮。平面采用高粗糙度材质，不添加会破坏此关系的扰动法线。无需额外投影相机或自制合成字母图层。

`src/home/receiver.js` 为黑色接影面增加圆形入射光范围：在平面的局部坐标中，仅衰减直接光照，`smoothstep(0.50, 8.0, radius)` 形成宽幅柔和渐变，再乘以 `1.0 - 1.0 * min(radius² / 64.0, 1.0)` 加深外围衰减；64.0 是外半径 8.0 的平方。当前墙面交界距离中心 4.4，直接光仍保留约 33%，三面光晕自然连通，参考原书封面的大面积光晕。圆形在透视画面中自然呈椭圆；其范围覆盖木雕在任意旋转下的投影包围球。间接光在墙面上大幅减弱，让字母影子与未照亮的墙面均保持深色。这个 shader **只模拟光束范围，不生成或替换阴影**；字母及旋转后的所有影子仍由原生阴影映射得到。保留平行光可避免有限距离聚光灯引起投影变形。

使用 Three.js 原生 WebGL 阴影映射和 `PCFShadowMap`。桌面使用三张 2048² 阴影图，窄屏初次加载时使用 1024²。阴影正交范围为 ±2.65，覆盖雕塑在任意旋转下的包围球；near/far、bias、normalBias 和适度 PCF 半径在 `src/home/scene.js` 中统一配置。木雕会自投影，接影面不会向其他面投影。适量暖色环境光让暗部仍可辨认。

没有在木雕上画字母，没有预渲染阴影，没有根据观察角度切换模型。木纹只是基于模型局部坐标的程序化材质，随木雕一起转动，不参与阴影生成。

## 操作与渲染

- 左键拖动或单指拖动：围绕固定相机的上/右向量旋转木雕，支持水平和竖直方向。
- 放开即停，不自动旋转，无惯性，无缩放或平移。
- **Reset**：520ms quaternion slerp 回到精确的单位四元数；开启减少动态效果时立即复位。
- 也可聚焦画布后用方向键旋转，没有额外可见控件。
- 使用 pointer capture，处理取消和失去捕获；忽略额外触点和非左键。
- 仅在拖动、复位、尺寸变化和恢复显示时申请绘制，静止时不持续占用渲染循环。
- 限制 pixel ratio 为 1.75，监听容器尺寸；离屏/后台暂停，返回后刷新，退出时释放 GPU 资源。

## 文件结构

```text
geb/
├── src/
│   ├── index.html                 # 首页源码
│   ├── home/                      # 首页脚本、样式和木雕场景
│   └── chapters/00-intro/
│       ├── index.html             # 人物介绍与三分页框架
│       ├── main.js
│       └── style.css
├── shared/geb.css                 # 通用主题、基础布局和导航
├── assets/model/                  # 模型与诊断文件
├── assets/app/                    # 生成的浏览器资源
├── scripts/
├── tests/
├── package.json / package-lock.json
├── vite.config.js
├── index.html                     # 生成的首页
├── chapters/00-intro/index.html    # 生成的章节页
└── dist/                          # 完整构建结果，不提交
```

只编辑 src/ 中的页面；首页专用模块在 src/home/，章节源码在 src/chapters/<编号-名称>/，每章包含 index.html、main.js 和 style.css。Vite 自动发现各章 HTML 入口，发布脚本同步首页、chapters/ 和 assets/app/；这些静态产物随源码提交。dist/ 包含所有已实现页面，可独立预览整个项目。发布脚本不自动清理历史产物，删除或改名页面时需检查旧发布文件。

第三方依赖统一使用 npm 和 package-lock.json 管理，由 Vite 打包为本地静态资源，不另建手动 vendor/。每章只导入自身所需依赖；shared/ 保留自行编写的跨页面代码，首页专用样式已移到 src/home/style.css。素材按需添加，记录来源与授权。



## 已知边界

- 模型为原创的块状 G/E/B 视觉壳，不是原封面木雕的精确复制；切角有细微体素台阶，没有圆滑倒角。
- 投影测试的 100% 指 96×96 离散轮廓及导出的网格。屏幕上仍会有正常的透视压缩、PCF 边缘和少量木雕自身遮挡。
- 除初始/复位位置外，任意旋转后的影子通常不会继续像字母，这正是本互动要展示的现象。
- 需要 WebGL 2。资源均本地提供；无法创建图形上下文时显示文字提示。
- 目标是现代桌面流畅交互，尚未跨设备实测 60 FPS；移动端图形性能取决于设备。
- 首页下一章指向 `/geb/chapters/00-intro/`，已实现三个人物分页与简介；哥德尔分页含第一不完备性定理双分支互动、准确性说明与意义讲解，埃舍尔分页已加入含周围房屋、露台楼梯、植物与版画纹理的内联 SVG 动画场景（位于 src/chapters/00-intro/escher/，当前回到柱廊与平台结构校对：左塔上/中和右塔上/下各为四柱，左塔下为右侧双方柱，平台仅在水磨房与水轮下方；四条水道各拆成无缝衔接的左右两半，按各个转角的关系与柱廊交错绘制；水道4与水道2平行；渠道加宽并绘制有厚度的双侧墙，墙高按每段两次增高的三级台阶排列（砖层1/2/3、3/4/5、5/6/7、7/8/9），转角柱脚标高固定，渠底与可见水面单独拟合，转角完整承托外侧柱脚。水道、塔楼与磨坊按最新构图整体上移，下方承托建筑加高；projection.js 统一渠岸、四柱方阵、拱梁及檐口的平面角度（朝右向下10°、向上20°，锐夹角30°），左塔下双柱缩短并与中层右柱对齐；水轮水平镜像，轮厚沿向右下10°投影，半径64、整轮24片叶板，按渠岸边界定位；拱梁由arches.js绘制实体内壁、拱脚及拱石接缝，中段顶部方块与转角渠底封闭露底；背景梯田的台地、挡墙、石缝/耕地排线及稀疏植物位于landscape.js，背景三段阶梯已移除，左上高窄屋按原作单独定位；pond.js绘制接瀑布落水的封闭方形池及涟漪，后沿靠方柱，前/左右边保持铺地间距，已删除与水道4的独立连接水带，按ESCHER-LANDSCAPE-PLAN.md分轮廓草图、实体连接、版画细节三阶段验收重绘，拱梁覆盖完整柱头，左塔下双方柱等长；buildings.js 统一房屋、楼梯和平台的投影角度，柱脚直接位于水道上，塔顶分别为三立方体复合体和菱形十二面体第一星形化；水道流纹沿4→3→2→1运动，瀑布快速下落并带雾状及飞溅水花；水车采用投影前圆轮旋转与后层叶板向下循环，30秒一圈；支持播放/暂停、分页切换/离屏/后台暂停及减少动态效果），巴赫分页已接入“两只老虎”的真实音符与卡农播放，支持五声部、整小节拖动、独立混音、七档调速与循环。其他候选曲目等待素材，录音准备流程见 CANON-WORKBENCH-PLAN.md；下一章链接指向尚未开发的 01-mu。
